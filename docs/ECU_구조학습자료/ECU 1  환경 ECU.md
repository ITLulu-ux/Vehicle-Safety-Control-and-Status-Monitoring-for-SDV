2\. SysTick Interrupt



&#x09;\*\*FreeRTOS 때문에 반드시 사용됨\*\*



STM32에는 SysTick Timer 라는 타이머가 있음 보통 1ms마다 Tick발생 즉 0ms -> 1ms -> 2ms -> ... 계속 인터럽트 발생



FreeRTOS는 이 Tick을 이용해서 Task A -> Task B -> Task C 를 언제 실행할지 결정함.



&#x09;	예를 들어

Sensor Task = 100ms마다 실행	CAN Task = 50ms마다 실행 이라고 하면 SysTick이 계속 시간을 세고 있음



Sensor Task / CAN Task -> 50ms(CAN Task) -> 100ms(Sensor Task / CAN Task) -> 150ms(CAN Task)





3\. 

DHT11과 BH1750는 인터럽트를 지원하지 않는 센서이므로, FreeRTOS의 Sensor Task에서 일정 주기로 값을 읽는 Polling 방식을 사용합니다.

이는 센서의 측정 주기(수백 ms\~수 초)가 비교적 길고, 실시간 인터럽트 처리가 필요하지 않기 때문입니다.

**ECU1에서 왜 Semaphore를 사용할까?**



**ECU1은 평소에**



**Sensor Task**

**↓**

**CAN TX Task를 실행합니다. 그런데 갑자기**



**ECU4**

**↓**

**CAN Message 전송이 들어왔다고 생각해봅시다.**



**CPU가 계속**

**CAN 왔나?**

**CAN 왔나?**

**CAN 왔나?**

**CAN 왔나?**

**확인하면 CPU를 낭비하게 됩니다.**



**그래서 CAN Peripheral가 메시지가 들어오면 CPU에게 "CAN 왔습니다!"라고 알려줍니다.**



**이게 CAN RX Interrupt입니다.**



**------------------------------------**



**| Semaphore                   | 송신                 | 수신             | 역할                                                                                             |**

**| --------------------------- | -------------------- | --------------- | -----------------------------------------------------------------------------------------------  |**

**| \*\*CAN RX Binary Semaphore\*\* | \*\*CAN RX Interrupt\*\* | \*\*CAN RX Task\*\* | CAN 메시지가 수신되면 인터럽트에서 Binary Semaphore를 해제(Give)하여 CAN RX Task를 즉시 실행시킨다. |**

&#x09;								 **Task는 Semaphore를 획득(Take)한 후 CAN 수신 데이터를 읽고 필요한 처리를 수행한다. 		  |**



**설계 의도**

**-	인터럽트에서는 최소한의 작업(세마포어 Give)만 수행하여 인터럽트 처리 시간을 최소화한다.**

**-	CAN RX Task가 실제 데이터 처리를 담당하여 응답성과 시스템 안정성을 높인다.**

**-	폴링 방식 없이 이벤트 기반(Event-driven)으로 동작하므로 CPU 사용률을 줄이고 실시간성을 확보할 수 있다.**
